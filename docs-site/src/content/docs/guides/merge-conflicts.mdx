When a merge, rebase, cherry-pick, or revert stops on conflicts, GitLane
switches into a conflict workspace. You don't have to go find a terminal to
finish the operation.

## Resolving

<Steps>
  <Step title="Pick a file">
    Conflicted files are listed with what kind of conflict each one is.
  </Step>
  <Step title="Resolve">
    Work hunk-by-hunk in an inline or side-by-side editor, picking per line
    where you need to. For a file you don't need to be surgical about, take
    **ours** or **theirs** wholesale.
  </Step>
  <Step title="Continue, skip, or abort">
    Once the conflicts are resolved, continue the operation — or skip this
    commit, or abort the whole thing and return to where you started.
  </Step>
</Steps>

## Resolve with AI

When an in-app agent is configured, the conflict workspace offers **Resolve
with AI** for a text conflict — optionally with a note for the agent — and
**Resolve all** for every conflicted file. Either way it's one agent session
with one prompt, so the agent sees all the files together and resolves
related conflicts consistently. The answer is split back per file: each
proposal lands in Output so you can review it, then **Apply & stage** or
discard it. A file the agent got wrong — missing, empty, still holding
markers, or changed on disk meanwhile — errors on its own; the rest still
land. **Stop** on any file ends the whole run and cancels the agent;
resolving a file by hand takes only that file out of the run. The agent sends
back only the replacement lines for each conflict, so a small conflict in a
large file comes back quickly.
The same [agent rules](/guides/settings) as Draft apply: no auto-approved
writes, read-only `git` only.

## The awkward cases

**Binary conflicts** and **modify/delete conflicts** are handled explicitly
rather than dumped on you as raw markers.

**Resolved outside GitLane?** If you fixed a file in your own editor, stage
it as-is — GitLane accepts the file as the resolution.

**Changed your mind?** A staged resolution can be un-staged so you can redo
it.

<Aside type="note" title="This is real git the whole way through">
  The conflict machinery is git's own, because writes shell out to your `git`
  binary rather than reimplementing merge in-process. A conflict GitLane
  shows you is exactly the conflict a terminal would show you, and an
  operation you abort here aborts the same way.
</Aside>
